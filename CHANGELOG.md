### Для оболочки `buyer_agent`

| `next` | Что делает оболочка |
|---|---|
| `NEW_MANDATE` | запросить у человека новое поручение |
| `ASK_HUMAN` | передать решение человеку (например, `LIMIT_EXCEEDED`, `CONFIRMATION_REQUIRED`) |
| `NOTIFY_HUMAN` | сообщить человеку без решения (отказ банка, `OPERATION_RESULT_UNCONFIRMED`) |

Когда наружу ушла исходная ошибка шага (например, `PlatformFailure`), а не `PurchaseStopped`, — читайте `purchase.next` и `purchase.unfinished`.

**2. Отзыв поручения — `STOP_ALL` (Т13).** Код `MANDATE_REVOKED` (ответ Платформы, а также отзыв, замеченный при проверке поручения перед шагом и при ожидании подписи) и причина `DECLINED_MANDATE_REVOKED`. | `unfinished` | Когда | Текст человеку (`UNFINISHED_TEXT`) |
|---|---|---|
| `SEARCH` | остановка на поиске | «Не завершено: поиск товаров по поручению. Покупка остановлена.» |
| `CHOICE` | выдача без выбора | «Не завершено: выбор товара. Покупка остановлена.» |
| `ORDER` | корзина есть, заказа нет | «Не завершено: заказ у продавца не создан. Покупка остановлена.» |
| `PAYMENT` | заказ создан, оплаты нет — до отправки оплаты **и после известного отказа `DECLINED_*`** | «Не завершено: оплата не прошла, заказ у продавца создан и не оплачен; итог проверьте в приложении банка. Отменить заказ можно у продавца.» |

| `NO_RESPONSE` | тайм-аут или сбой сети до заголовков ответа — исход на Платформе неизвестен | `same_key` — ядро уже повторило тем же ключом до `pao_max_attempts` (изменяющие методы, кроме выдачи реквизита); `never` — у `GET` и выдачи реквизита | не повторять покупку новым ключом; человеку — текст реестра («итог проверьте в приложении банка») |
| `BAD_RESPONSE` | ответ Платформы вне контракта ПАО: 2xx не по схеме, пара «код, HTTP» не по `x-pao-errors`, ответ без тела ПАО, оборванное тело | `never` | остановка; **покупку новым ключом не повторять** — при 2xx на изменяющий запрос действие на Платформе, вероятно, выполнено; сверка состояния по `GET` — в ядре с AG-12 ч. 2 |
| `AGENT_REQUEST_DEFECT` | дефект агента: пустой `Idempotency-Key`, обращение не отправлено | `never` | остановка; ошибка вызывающего кода — сообщить разработчику, человеку — технический текст реестра |

`UNKNOWN` остаётся для кода вне ПАО 1.4.0 и прочего неопознанного (в том числе отказа до сети по значению запроса — к пересмотру в AG-12 ч. 2, Р48 дополнение 1 (б)).

**2. Допуск при `NO_RESPONSE` не останавливает агента.** Если `core.start()` отказал с `AgentNotReady` и кодом `NO_RESPONSE` (реестр не ответил), подписант не остановлен: `start()` можно вызвать снова. До успешного допуска подпись отказывает с `SignerStopped` и причиной `NOT_ADMITTED`. Своего цикла повтора допуска в ядре пока нет — повтор за вызывающим (Р48 дополнение 1 (а), цикл — AG-12 ч. 2). При `BAD_RESPONSE` (ответ реестра не по схеме) — остановка, как раньше (прежде такой случай назывался `UNKNOWN`).

**3. Причины отклонения операции (`declineReason`, SPEC §7б) — закрытый перечень Платформы v0.19.0 (передача #57).** Новые коды остановки покупки на стадии 5:

| Причина Платформы | Код остановки |
|---|---|
| `AGENT_SUSPENDED` | `DECLINED_AGENT_SUSPENDED` |
| `CREDENTIAL_INVALID` | `DECLINED_CREDENTIAL_INVALID` |
| `MANDATE_NOT_FOUND` | `DECLINED_MANDATE_NOT_FOUND` |
| `MANDATE_EXPIRED` | `DECLINED_MANDATE_EXPIRED` |
| `MANDATE_REVOKED` | `DECLINED_MANDATE_REVOKED` |
| `MANDATE_SCOPE` | `DECLINED_MANDATE_SCOPE` |
| `LIMIT_EXCEEDED` | `DECLINED_LIMIT_EXCEEDED` |
| `STATE_UNAVAILABLE` | `DECLINED_STATE_UNAVAILABLE` |
| `ISSUER_DECLINED` | `ISSUER_DECLINED` (до ПАО 1.5.0 так приходит и нехватка средств) |
| `AOI_MISSING`, `AOI_MISMATCH`, `INSUFFICIENT_FUNDS` | прежние коды |

Повтора операции нет ни у одной причины. **Тексты человеку не советуют повторить покупку** и все содержат «итог проверьте в приложении банка»; прежние тексты `INSUFFICIENT_FUNDS` («Пополните счёт или выберите другой способ оплаты») и `UNKNOWN` («Повторите позже») заменены. Оболочка не добавляет свой совет повторить. Действия по причине (новый мандат, остановка всего по мандату) ядро исполняет с AG-12 ч. 2; реакция на событие `operation.declined` — с AG-12 ч. 3.

**4. Пометка Д02 (Р48 п. 5).** Если продавец создал заказ на сумму, отличную от итога корзины (остановка `ORDER_REPLY_MISMATCH`), в следующих выдачах этого процесса позиция продавца приходит с сигналом `A5_PRICE_MISMATCH` в `Offer.a5` — тем же, что у противоречивого описания (П09). Зона прежняя. Корзина — только по явному решению человека (`HumanA5Decision` из оболочки, как для П09); в автономном режиме — `A5_AUTONOMOUS`. Пометка живёт в памяти процесса и теряется при перезапуске ядра. В журнале — запись `offer.flagged` с `detail: ORDER_REPLY_MISMATCH`.

### Для оператора агента

- `idempotency_ttl_sec` (PARAMS) теперь рабочий: бюджет повторов тем же ключом (`pao_max_attempts × pao_request_timeout_ms + 30 с`) не больше него, иначе агент не запускается. **До PS-05 он равен сроку хранения ключа на стенде — 86 400 с**; затем — из `/.well-known/pao-configuration` Платформы (Р48 дополнение 1 (в)).
- Выпуск для реальных платежей — по-прежнему после AG-11 ч. 2 и AG-13 ч. 2.
