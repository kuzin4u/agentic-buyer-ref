Передача для AG-03 (из STATUS платформы, раздел «Передача агенту»):
- код агента — `nspk:agent:<id>:v<N>`;
- `kid` — отпечаток JWK по RFC 7638 в base64url; агент вычисляет его сам (эталон — RFC 8037, прил. A.3);
- `public_key` — DER SPKI в канонической записи base64 (RFC 4648 §3.5, не base64url); лишние биты перед «=», без дополнения, пробелы — `KEY_INVALID` (РП23 доп. 6 платформы, v0.1.1);
- слабые ключи Ed25519 платформа отклоняет кодом `KEY_INVALID`;
- `Retry-After` у ответа 503 — не больше 30 с;
- `GET /pao/v1/agent` подписывается с `content-digest` пустого тела.
- **РП26 (SEC-1; код — PS-05, PS-08, ПАО 1.3.0):** ответы и события Платформы подписываются по RFC 9421 (метка `platform`, `created` в окне `signature_skew_sec`; ответ привязан к запросу через `@method;req`, `@path;req`, `x-nonce;req`). Ключи — в `platform_keys` `/.well-known/pao-configuration`, проверять `use` (ключи ответов и событий разные); неизвестный `kid` — одно перечитывание конфигурации, затем отказ; `REVOKED` — отказ. Проверка — `verifyResponse` agentic-core (задача к CO). В копии ПАО 1.2.0 агента подписи ответов нет — до 1.3.0 (AG-06).
- **РП27 (SEC-1; код — PS-05):** mTLS песочницы — ключ сертификата генерирует оператор агента и передаёт CSR; сертификат выпускает УЦ песочницы, код агента — в SAN URI `urn:nspk:agent:<id>:v<N>`. Код из сертификата ≠ `x-agent-code` — `AGENT_UNKNOWN`; истёкший или отозванный сертификат — `AGENT_KEY_REVOKED` (`new_key`). Новых кодов нет; приостановление и исключение сертификат не отзывают. До переезда хранилища перезапуск песочницы = повторный допуск агента (SECURITY.md §6 платформы).

Передача для AG-04, AG-09, AG-11 — PS-12 (STATUS платформы v0.2.0, «Передача агенту»; эмулятор — источник истины по Р26 агента):
