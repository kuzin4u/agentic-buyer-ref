# Запуск: что сделать владельцу

Около 20 минут. После этого первая сессия в Claude Code идёт по плану из `docs/core/STATUS.md`.

## 1. Репозиторий на GitHub

Создайте открытый (Public) репозиторий `agentic-buyer-ref` — README допустим, комплект его заменит. Видимость можно сменить позже в настройках репозитория.

## 2. Клон и распаковка

```bash
cd ~/repos
git clone https://github.com/<ваш-аккаунт>/agentic-buyer-ref.git
cd agentic-buyer-ref
git checkout -b claude-setup
# распакуйте архив так, чтобы содержимое папки agentic-buyer-ref легло в корень клона
cp -R ~/Downloads/agentic-buyer-ref/. .
git add -A
git commit -m "Комплект: документы, команды, хуки, CI"
git push -u origin claude-setup
```

Затем откройте Pull Request `claude-setup → main` и слейте его. CI должен быть зелёным: проверка каталога сценариев, типов и поиск секретов.

## 3. Защита ветки main

GitHub → Settings → Branches → правило для `main`: запрет прямых пушей, обязательный зелёный CI перед слиянием.

## 4. Ключ модели (не сейчас)

Нужен только с этапа 3. Тогда скопируйте `.env.example` в `.env` и впишите `ANTHROPIC_API_KEY`. Claude Code `.env` не читает и не пишет — это запрещено настройками и хуком.

## 5. Проверка комплекта

```bash
cd ~/repos/agentic-buyer-ref && claude
```

В Claude Code:
- `/check-setup` — ваша глобальная проверка комплекта;
- `/start` — начало первой сессии.

## 6. Решения до сессии 2

В `docs/core/DECISIONS.md` записаны Р1–Р13. Прочитайте и либо подтвердите, либо скажите в сессии: `/decision Р3 меняется: …`. Особенно важны:
- **Р3** — агент платит только в контуре гарантий, вне контура даёт ссылку;
- **Р4** — эскроу как подключаемый режим, в эталонном прогоне выключен;
- **Р11** — стек TypeScript / Node / Express;
- **Р12** — отдельный репозиторий, не `buyer_agent`;
- **Р14** — приёмка против песочницы Платформы (`agentic-ps-platform`) по ПАО v1;
- **Р15** — здесь ядро без модели, диалог — в `buyer_agent`;
- **Р17** — сделки НСВР — адаптер ядра, отдельного агента нет.

Сначала опубликуйте `agentic-core` с тегом `v0.1.0` — от него зависит этот репозиторий.

## Что в комплекте

| Путь | Что это |
|---|---|
| `CLAUDE.md` | Правила, 10 инвариантов агента, стек, структура кода |
| `docs/core/` | ТЗ агента и эмулятора, контракт OpenAPI, нормы, 30 сценариев, параметры, решения, план, статус |
| `docs/reference/` | Обзорная страница и исходный пул — только чтение |
| `config/params.stand.json` | Стендовые значения параметров |
| `tests/scenarios/` | Каталог сценариев (JSON) и тест его согласованности |
| `.claude/commands/` | `/start`, `/finish`, `/task`, `/audit`, `/verify`, `/decision`, `/scenario` |
| `.claude/agents/reviewer.md` | Проверяющий подагент с чек-листом из 18 пунктов |
| `.claude/hooks/` | `guard.py` (защита), `log_tool.py` (журнал), `session_summary.py` (сводка), `scan_secrets.py` (поиск ключей и реквизитов) |
| `.claude/settings.json` | Запреты и подключение хуков |
| `.github/workflows/ci.yml` | Проверка на каждый PR |

## Что защищено и как

| Что | Как |
|---|---|
| `git push`, создание и слияние PR | запрет в настройках + хук |
| `.env`, `*.pem`, `*.key` — чтение и запись | запрет в настройках + хук (в том числе `cat`, `grep`, `head` через Bash) |
| `docs/reference/` — запись | запрет в настройках + хук по цели записи (`>`, `>>`, `tee`, `sed -i`, `cp`/`mv` в этот путь); чтение разрешено |
| `.claude/hooks/` — правка самим Claude | хук |
| Ключ `sk-ant-`, приватный ключ, номер карты в коде | хук при записи + сканер в CI |
| Коммит, `npm install`, `curl` | спрашивает разрешения |

Ограничение: защита на стороне Claude Code не заменяет защиту ветки `main` на GitHub и хранение секретов вне репозитория.
