Передача для AG-03 (из STATUS платформы, раздел «Передача агенту»):
- код агента — `nspk:agent:<id>:v<N>`;
- `kid` — отпечаток JWK по RFC 7638 в base64url; агент вычисляет его сам (эталон — RFC 8037, прил. A.3);
- `public_key` — DER SPKI в канонической записи base64 (RFC 4648 §3.5, не base64url); лишние биты перед «=», без дополнения, пробелы — `KEY_INVALID` (РП23 доп. 6 платформы, v0.1.1);
- слабые ключи Ed25519 платформа отклоняет кодом `KEY_INVALID`;
- `Retry-After` у ответа 503 — не больше 30 с;
- `GET /pao/v1/agent` подписывается с `content-digest` пустого тела.
- **РП26 (SEC-1; код — PS-05, PS-08, ПАО 1.3.0):** ответы и события Платформы подписываются по RFC 9421 (метка `platform`, `created` в окне `signature_skew_sec`; ответ привязан к запросу через `@method;req`, `@path;req`, `x-nonce;req`). Ключи — в `platform_keys` `/.well-known/pao-configuration`, проверять `use` (ключи ответов и событий разные); неизвестный `kid` — одно перечитывание конфигурации, затем отказ; `REVOKED` — отказ. Проверка — `verifyResponse` agentic-core (задача к CO). В копии ПАО 1.2.0 агента подписи ответов нет — до 1.3.0 (AG-06).
- **РП27 (SEC-1; код — PS-05):** mTLS песочницы — ключ сертификата генерирует оператор агента и передаёт CSR; сертификат выпускает УЦ песочницы, код агента — в SAN URI `urn:nspk:agent:<id>:v<N>`. Код из сертификата ≠ `x-agent-code` — `AGENT_UNKNOWN`; истёкший или отозванный сертификат — `AGENT_KEY_REVOKED` (`new_key`). Новых кодов нет; приостановление и исключение сертификат не отзывают. До переезда хранилища перезапуск песочницы = повторный допуск агента (SECURITY.md §6 платформы).

Передача для AG-04, AG-09, AG-11 — PS-12 (STATUS платформы v0.2.0, «Передача агенту»; эмулятор — источник истины по Р26 агента):
- фикстуры: `MERCHANT_FIXTURES`, `AGENT_FIXTURES`, `agentApplication` из `agentic-ps-platform/fixtures` — тот же источник, что витрины; у витрины `items` (как видит человек) и `agent_items` (как видит опознанный агент: у SHOP-3303 цена ниже); закрытых ключей у агентов нет — пару генерирует потребитель, `agentApplication(f, { alg, public_key })` → `stand.admit(…, f.operator)`; `registered: false` — агент заведомо не в реестре;
- витрины: `createMerchants(stand, { aoiSupport?, decide? })` из `agentic-ps-platform/stand` → `app`, `listen()`, `opkc.messages`, `reconciliation`; подпись агента витрина проверяет по каталогу ключей реестра стенда — ключ должен быть зарегистрирован;
- список витрин — по `CONTOUR.md` (ред. 2, по фикстурам): SHOP-1042, MKT-77, SHOP-4401, SHOP-3301, SHOP-3302, SHOP-3303, SHOP-2210, SHOP-5003 и новая **SHOP-5501** — неполное описание (A5 п. 1.1), заказ без цены — 422 `ITEM_INCOMPLETE`; сценарий — `/decision` в AG-09 (решение владельца 13.10.2026);
- знак готовности у SHOP-3301 и SHOP-3303 стоит: витрины «до обнаружения», агент ловит нарушение сам, не опираясь на знак; зону определяет знак (РП22 п. 7 платформы);
- адреса: `GET /v1/shops` → `{shops}` (`merchant_id` `MER-…` ≠ id витрины), `GET /v1/shops/{id}/catalog?query&limit` → `{shop, items}`, `POST /v1/shops/{id}/orders` с телом `{items: [{sku, qty}], cart_mandate_id}` — **мандат корзины, поле `cart_mandate_id`, не `mandate_id`**; `POST /v1/shops/{id}/orders/{order_id}/payment` с `PaymentPackage` (`order_ref` = id заказа, `cart_mandate_id` = мандат заказа, `aoi.agent_code` = подписант);
- `PaymentPackage` (РП22 платформы): `credential_ref`, `kind`, `payload`, `aoi`, `cart_mandate_id`, `order_ref`, подпись агента RFC 9421 тем же ключом; **суммы в пакете нет**; продавцы проверяют подпись по каталогу JWKS (`kid` = `Key.kid` ПАО, `agent_code`, `nbf`, `exp`);
- заказ и оплата — только подписанным агентом (без подписи — 403 `AGENT_UNIDENTIFIED`); сумма заказа — по цене продавца, `total` из запроса не читается; ответ на оплату — только `payment: {approved}`, `op_ref` и код решения — событием Платформы (PS-16; инвариант 8);
- отказы витрины по подписи: `KEY_UNKNOWN` (нет в каталоге — не допущен, отозван, приостановлен), `AGENT_MISMATCH` (ключ другого агента), `KEY_EXPIRED`, `SIGNATURE_INVALID`; сбой каталога — 503; ошибки витрин — `{code}` эмулятора, не ПАО §6;
- прочие отличия от `openapi.yaml` — расхождение № 17 платформы (здесь № 19), закрыто Р26 агента: правим агента под эмулятор, `openapi.yaml` заморожен.
