## 1. Назначение

Агент — эталонная реализация добросовестного агента покупателя в контуре оператора. Он служит мерой для других агентов и измерительным прибором: прогон заполняет параметры, помеченные в драфтах «[указать]».

Коммерческие функции (персонализация, реклама, ранжирование по выгоде для продавца) в задание не входят и при испытаниях отключаются.

## 2. Классификация

- **По правам (класс в реестре):** агент покупателя. Вправе инициировать заказ и платёж в пределах мандата (A2 п. 2.1).
- **По устройству:** агент-цепочка. Детерминированный конвейер стадий; языковая модель используется только в диалоге и поиске (Р8).
- **Принципал:** человек-покупатель. **Оператор агента:** юридическое лицо, включённое в реестр.

## 3. Границы

Агент **не делает** следующего:
- не выбирает за человека вне мандата;
- не хранит и не видит реквизиты;
- не ведёт состояние бюджета;
- не формирует запись об исполнении — это делает оценивающий участник (A1 п. 6.2);
- не оценивает качество товара;
- не исполняет платёж у продавца вне контура гарантий (Р3).

## 7. Поведение на отказы

По Р20. Источник кодов и `retry` — ПАО 1.2.0 (`docs/core/protocol/`, §6). Повтор — всегда с новой подписью (новые `x-nonce` и `x-timestamp`) и прежним `Idempotency-Key` (Р21).

### 7а. Ошибки ПАО

Коды отказа ядра — словарь ядра (`FailureCode` в `src/shared/domain.ts`); любой адаптер платформы (pao, будущий адаптер НСПК) переводит свои коды в него, неизвестный код — `UNKNOWN` (остановка).

| Код | HTTP | `retry` | Поведение ядра |
|---|---|---|---|
| AGENT_UNKNOWN | 401 | never | Остановка; сообщение оператору агента о допуске |
| AGENT_SUSPENDED | 403 | never | Остановка до `agent.reinstated` |
| AGENT_KEY_REVOKED | 401 | new_key | Подписать действующим новым ключом; если его нет — остановка |
| SIGNATURE_INVALID | 401 | after_fix | Проверить время и состав подписываемых полей; один повтор, затем остановка |
| MANDATE_NOT_FOUND | 404 | after_human | Запросить у человека новый мандат |
| MANDATE_EXPIRED | 409 | after_human | Запросить у человека новый мандат |
| MANDATE_REVOKED | 409 | never | Остановить всё начатое; сообщить, что не завершено |
| MANDATE_SCOPE | 409 | after_human | Сообщить; повтор только по новому мандату |
| PRINCIPAL_SIGNATURE_PENDING | 409 | after_human | Ждать `mandate.signed`; без подписи не продолжать |
| LIMIT_EXCEEDED | 409 | after_human | Уведомить человека; повтор после изменения лимита человеком |
| STATE_UNAVAILABLE | 503 | same_key | Не действовать по устаревшему состоянию; повтор тем же ключом в пределах `registry_cache_ttl_sec`, затем остановка |
| CONFIRMATION_REQUIRED | 428 | after_human | Передать решение человеку; после подтверждения — повтор тем же ключом; дробление запрещено |
| CREDENTIAL_INVALID | 409 | after_fix | Реквизит не использовать; новый реквизит — только при действующем мандате CART |
| CREDENTIALS_FORBIDDEN | 422 | never | Нарушение инварианта 1; остановка; прогон отмечается |
| IDEMPOTENCY_REQUIRED | 400 | same_key | Дефект агента; событие в журнал; повтор с ключом |
| IDEMPOTENCY_CONFLICT | 409 | after_fix | Дефект агента (тот же ключ, другое тело); остановка операции, событие в журнал |
| RATE_LIMITED | 429 | same_key | Ждать `Retry-After`; повтор тем же ключом в пределах `registry_cache_ttl_sec` |
| UPSTREAM_UNAVAILABLE | 503 | same_key | Как STATE_UNAVAILABLE |
| неизвестный код | — | — | Остановка; событие в журнал |

Причина остановки ядра вне перечня ПАО (в таблицу не входит): `AGENT_CLASS_MISMATCH` — класс агента в реестре (`GET /pao/v1/agent`, поле `class`) не BUYER. Проверяется после статуса, при допуске и при каждой сверке с реестром; остановка без повторов, класс из реестра — в журнал, сообщение оператору агента. Ответ `GET /pao/v1/agent` с HTTP 2xx не по схеме (не JSON, пустое тело, нет `class`, класс или статус вне перечня, неполный список ключей) — `UNKNOWN`: на допуске допуск не состоялся (повторить можно); после допуска — приостановка подписи `AGENT_SELF_UNKNOWN` до успешной повторной сверки, не бессрочно (Р27).

### 7б. Причины отклонения операции (`operation.declined`, поле `reason`)

| Причина | Поведение ядра |
|---|---|
| AOI_MISSING | Дефект агента: пакет без признака; исправить агента (операцию не повторять); событие в журнал |
| AOI_MISMATCH | Инцидент; остановка |
| INSUFFICIENT_FUNDS | Уведомить человека; без повтора |
| иная или неизвестная | Остановка по этой операции; уведомить человека; без повтора; событие в журнал (Р20, уточнение 11.10.2026) |

В ПАО 1.2.0 `reason` — свободная строка; перечень сверяется с платформой при PS-16.

## 8. Нефункциональные требования

- Время ответа на действие человека — единицы секунд; длительные операции с уведомлением о ходе.
- Полная воспроизводимость: по журналу восстанавливается каждое решение и сопоставляется с мандатом.
- Работа без внешних сервисов вне контура испытаний. Модели в ядре нет; сценарии прогоняются с тестовыми советчиками, продуктовый `buyer_agent` — со своим.
- Версия модели и среда исполнения фиксируются в реестре; смена модели — новая версия кода агента (A2 п. 4.4).
- Минимизация данных: принципал — только ссылкой `principal_ref`.
- Подпись (Р21, по ПАО §2): ed25519; подписываемые поля — `@method`, `@path`, `@query`, `content-digest`, `x-agent-code`, `x-timestamp`, `x-nonce`. У запросов без тела `content-digest` — от пустого тела. Окно времени — `signature_skew_sec`; `x-nonce` не повторяется в пределах окна. Каждый повтор (`same_key`, `after_fix` и другие) — новая подпись с новыми `x-nonce` и `x-timestamp` и прежним `Idempotency-Key`; повтор nonce Платформа отклоняет (`SIGNATURE_INVALID`, РП23).
- Все суммы — `Money` agentic-core: целое число минимальных единиц валюты и код валюты (Р29). Валюта не из `PlatformCapabilities.currencies` — отказ (fail-closed); сумма без поля валюты у платформы — в валюте своего мандата.

## 9. Профиль contour: работа с Платформой ПС

- Протокол — ПАО v1, копия версии 1.2.0 (`docs/core/protocol/`, источник — `SOURCE.md`, Р20). Транспорт mTLS, подпись обращений с `x-nonce`, `Idempotency-Key`.
- Мандат запрашивает агент, подписывает человек в приложении банка; агент ждёт события `mandate.signed` и не продолжает до него. Событие — сигнал: мандат действует, когда `GET /pao/v1/mandates/{id}` вернул `ACTIVE`; событие при другом статусе — остановка; сверка остаётся и после проверки подписи событий (AG-06), Р29.
- Ответ `verify` без `as_of` или с `as_of` старше `registry_cache_ttl_sec` — `STATE_UNKNOWN`, вне пределов (A7 п. 8.6, Р29).
- Платёж: `POST /pao/v1/credentials` → пакет агентской оплаты продавцу → продавец проводит авторизацию через эквайрера → событие `operation.authorized` / `operation.declined` / `confirmation.required`.
- На `confirmation.required` агент передаёт человеку ссылку на страницу УПК или просит подтвердить в приложении банка; инструмент оплаты выбирает человек.
- Если сообщение продавца расходится с событием Платформы — агент верит Платформе и записывает расхождение.
- Поведение на ошибки — по полю `retry` ошибки ПАО и по таблице §7.

## 9а. Профиль platform

- Адаптер к Agent Service маркетплейса: уровень агента из реестра по `X-Agent-Code`, три контура ключей (RUNTIME / ADMISSION / READONLY), checkout по `Idempotency-Key`.
- Режим расчёта `escrow`: средства удерживаются в НСВР до подтверждения получения покупателем, затем раскрытие, сплит и выплата.
- Признак `source_type = AGENT` в заказе.
- Различия контрактов с `/v1` фиксируются в `STATUS.md`, раздел «Расхождения».

## 10. Вне задания

Условное исполнение как механизм контура `/v1`, трансграничные сценарии, оценка исполнения как действующий механизм (данные собираются), второй и третий каналы приёма (FAST, QR — только поле `channel`).

## 11. Критерии приёмки

1. Все положительные сценарии выполнены, все отрицательные отклонены с ожидаемыми кодами.
2. Ни один сценарий не пройден за счёт обхода нормы.
3. Сканер журнала прогона не находит реквизитов, ключей и `sk-ant-`.
4. Ни одного действия, вызванного текстом витрины или ответа продавца (Д01–Д03).
5. По журналу восстанавливается каждое решение и сопоставляется с мандатом.
6. `RunReport` содержит показатели исполнения и перечень расхождений «норма — практика»; параметры из `PARAMS.md` получили измеренные значения или обоснование, почему нет.
