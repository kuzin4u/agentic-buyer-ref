# ТЗ: эмулятор испытательного контура К1–К8

> Платёжная часть описана в репозитории Платформы (`agentic-ps-platform`). Этот файл описывает лёгкий мок для модульных тестов; приёмка — против песочницы Платформы по ПАО (Р14).

Редакция 1 · 08.10.2026 · основание: пул, файлы 22 (часть I) и 23.

## Зачем

Агенту нужен контур, против которого его проверяют, а настоящего контура пока нет. Эмулятор воспроизводит поведение, которое нормы A1–A9 требуют от оператора и банка: опознание, мандаты, ограничения, признак операции, авторизацию, споры, журнал испытаний.

Эмулятор **не торгует**, не выбирает товар, не хранит реальных реквизитов и не проводит реальных расчётов. Он проверяет соблюдение правил, а не качество советов.

Эмулятор пишется так же строго, как агент: он «полицейский» в сценариях. Если эмулятор пропускает нарушение, отрицательный сценарий ничего не доказывает.

## Порядок проверок в К5 `authorize`

Проверки идут до бизнес-логики, строго в этом порядке. Первая сработавшая даёт код отказа.

1. Подпись: ключ из реестра, окно времени, `content-digest` → `SIGNATURE_INVALID`, `AGENT_KEY_REVOKED`.
2. Агент в реестре и действует → `AGENT_UNKNOWN`, `AGENT_SUSPENDED`.
3. Реквизиты в теле (любое поле, похожее на номер карты, CVV, срок) → `CREDENTIALS_FORBIDDEN`.
4. Признак: есть `aoi.agent_code` и `aoi.mandate_id` → `AOI_MISSING`; код в признаке совпадает с подписью → `AOI_MISMATCH`.
5. `Idempotency-Key`: нет → `IDEMPOTENCY_REQUIRED`; уже был → вернуть прежний результат без повторного списания.
6. Мандат: найден, не истёк, не отозван → `MANDATE_NOT_FOUND`, `MANDATE_EXPIRED`, `MANDATE_REVOKED`.
7. Пределы мандата без состояния: получатель или категория, сумма не больше `amount_limit` → `MANDATE_SCOPE`.
8. Ограничения инструмента без состояния: разовая сумма → `LIMIT_EXCEEDED`.
9. Ограничения с состоянием: остаток за период, частота; неделимое расходование (блокировка позиции); если состояние недоступно → отказ как вне пределов (A3 п. 4.5) → `LIMIT_EXCEEDED` или `UPSTREAM_UNAVAILABLE`.
10. Дробление: совокупность операций по одному мандату в окне `split_window_sec`; если сумма больше `confirm_above_kop` при числе операций ≥ `split_min_ops` → отказ всех, `CONFIRMATION_REQUIRED`, событие «дробление».
11. Порог подтверждения → `CONFIRMATION_REQUIRED` (428); заказ в удержании на `order_hold_sec`.
12. Средства → `INSUFFICIENT_FUNDS`.
13. Успех: списание позиции бюджета, запись об исполнении (формирует К5, не агент), уведомление клиента о первом использовании полномочий.

При расхождении ограничений инструмента и пределов мандата применяется меньшее значение (A3 п. 7.2).

## Режимы деградации (для сценариев)

Эмулятор умеет по команде теста:
- отключать К1, К2 или К5 (ответ 503);
- задерживать распространение отзыва;
- переключать К3 в «мягкий режим рамки» — не проверять бюджет за период. Это нужно только для сценария спора вне мандата, чтобы показать последствие мягкой реализации (З01).

Управление — через тестовый хелпер, а не через публичный API.

## Среды

`dev` (всё в памяти) → `sandbox` (эмуляция с журналом на диске) → `pilot` (банк-участник выполняет К3 и К5). Коды агентов и мандаты сред не пересекаются. Переход между средами — по результатам прогона.
